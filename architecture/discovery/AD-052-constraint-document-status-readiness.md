# Constraint Document Status Readiness Norm Discovery

## 1. Gate-first and source rule

This discovery result is not positive-capable under OCP-016 G4. It classifies existing governance and status evidence; it adds no rule, result, profile, activation or status effect. Therefore G4 does not apply to this evidence form.

Only current governance norm may define promotion criteria. Repeated discovery vocabulary is practice unless governance defines it as an operation or criterion. The executable inventory applies that distinction before assessing OCP-006.

## 2. Norm versus discovery practice

OCP-001 and OCP-016 do not define `open-question-count`, a bounded stable surface, `blocks-whole-document-freeze` or a moving-surface classification as document-status criteria. Those four axes are useful vocabulary owned by AD-050 and its witness, but their repeated use does not promote them into norm. The executable absence guard binds both the machine tokens used by that witness and the natural prose forms by which each axis could enter governance; every bound form has its own mutation probe.

Current governance instead requires, criterion by criterion:

1. binding artifacts use a separate branch and draft PR, external adversarial review before a Board decision, an explicit Board decision, required checks and squash merge;
2. a triggered proposal names the exact candidate, applies current OCP-016, proposes one route and supplies the authority ledger, concrete consumers, exact dependencies, evidence, non-implications and migration/reopening effect;
3. `Accepted` means that the Board accepts the current document semantics as a basis for dependent specifications;
4. an OCP document promotion atomically carries version, status, readable compatibility surface, exact dependencies, evidence and repository accounting;
5. `Canonical` separately requires stable dependencies, machine-readable checks and a Board act;
6. a Canonical OCP additionally passes L2; and
7. the exact-head Fable/Codex/CI/Board gates and authorized squash merge are the only source of lifecycle effect.

No item in that list says all open questions must be closed. The checker binds every criterion to its exact current owner text and fails if the list or a source token drifts.

## 3. Complete precedent sweep

All 23 current primary OCP documents at `Accepted` or `Canonical` were inspected. The predeclared carrier criterion is current owner text that states an unresolved semantic question or choice; historical baselines, review prompts, backlog-status ledgers and explicitly closed reopening gates do not count.

Six promoted documents carry such current questions: OCP-002, OCP-003, OCP-004, OCP-007, OCP-008 and OCP-010. OCP-004, OCP-008 and OCP-010 expose current Open Questions sections; OCP-007 has a current section declaring material-event continuity unresolved; OCP-002 and OCP-003 state the unresolved Organization↔Resource mapping in current prose. A repository-wide lexical digest guards every current `unresolved`/`remain open` occurrence, including non-carriers and exclusions, so a future prose occurrence forces reclassification rather than passing silently. This precedent is not authority. It is consistent with the independently derived norm and would expose a practice/norm divergence if the norm had required an empty question set.

## 4. Criterion-by-criterion OCP-006 assessment

For `Draft → Accepted`:

- the binding review lane and exact-head lifecycle effect are pending a separate status act;
- exact OCP-006 identity, Architecture Board ownership, direct dependencies, current consumers and machine evidence exist;
- Route F appears only in OCP-016's precedent guide, which expressly forbids automatic reclassification, so a proposal-specific route and complete ledger remain pending;
- the exact dependencies and evidence are present, but the authorized atomic version/status/compatibility/accounting unit is not; and
- document acceptance is not implied by the already Accepted Constraint Concept.

Thus OCP-006 is not currently promoted or authorized, but its open-question inventory is not a normative bar. An Accepted transition is normatively possible only through a separately mandated complete status act.

For `Canonical`, the result is independently negative now. Machine-readable checks exist, but OCP-006 directly depends on OCP-005, which remains `Draft`; L2 therefore fails. No conclusion about maturity follows from that structural failure.

## 5. Boundary, versioning and rollback

This act changes no OCP-006 byte, version, status, question, blocker or candidate state. It changes no OCP-005 byte, Concept, graph or promotion cycle and authorizes no later act. OCP-006 remains `0.3.2 / Draft`, Constraint remains `Accepted`, and the Event cycle remains the only completed cycle with no active successor.

OCP-006 therefore has no version change. AD-052 is a new `0.1.0 / Discovery` evidence artifact. There is no data, reference or schema migration. Rollback removes only the AD-052 document, witness, checker integration, tests and derived accounting text as one unit.
